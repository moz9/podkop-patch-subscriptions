# Подписки и проверка DNS

## Подписки

Сначала выберите источники, теги и тип узлов. В автоматическом режиме ручные исключения не действуют. Тип «Игровые» определяется словом `Игровой` в названии; значок или протокол сами по себе не учитываются. Исключённые теги имеют приоритет над разрешёнными. Флаг и буквенный код одной страны считаются одним тегом.

Счётчик «К применению» учитывает несовместимые конфиги, выключенные источники, ручной выбор и фильтры. Каждому исключённому узлу назначается первая подходящая причина, поэтому итог не содержит двойного счёта. Значения на разных роутерах могут отличаться: подписки, настройки и результаты проверок у них свои.

В блоке сервисов показаны:

- «Подходят»: узлы со свежим положительным результатом всех выбранных проверок.
- «Свежие результаты»: узлы, у которых результаты всех выбранных проверок ещё действуют. Сюда входят также отказы и неопределённые ответы.
- «Нужна проверка»: новые узлы, неполные или устаревшие результаты.
- «Отказ» и «Не определено»: разные причины отсутствия допуска.

«Проверить новые/устаревшие» использует кеш. «Перепроверить всё» повторяет проверки для всего подходящего набора. Обновление подписки само не запускает проверку сервисов. Результаты действуют до 24 часов и привязаны к конфигу узла и контексту проверки. Истечение срока не переключает уже работающий прокси, но устаревший результат не даёт нового допуска.

### Проверки сервисов и страны

Все включённые условия обязательны; пустой набор отключает фильтр сервисов.

| Проверка | Что проверяется |
| --- | --- |
| Gemini | Регион в ответе публичной страницы Gemini. Это предварительная региональная проверка. |
| ChatGPT | Ответ каталога анонимных моделей веб-чата. |
| Страна по Google | Совпадение страны из названия узла с регионом в ответе Gemini. |
| Страна по IP | Совпадение страны из названия со страной выхода по IPWhois и IPinfo. |

Google и IP не проверяют друг друга. Совпадение страны по Google само по себе не означает доступность Gemini. Если включены оба условия Google, требуются оба результата, но используется один общий запрос. Фильтр по IP сохранён для совместимости и продолжает ограничивать набор, пока включён.

Для проверки совпадения нужна однозначная страна в названии: флаг или код. `EU` не является страной. При отсутствии страны, неоднозначном названии, расхождении IP-источников или ошибке проверки узел не допускается. Результаты и причины доступны в раскрывающемся блоке по узлам.

HTTP 200, страница входа или CAPTCHA не доказывают работу чата. Положительная предварительная проверка не гарантирует доступ аккаунта и ответ модели. Gemini/ChatGPT можно подтвердить вручную после сетевой проверки, если настоящий чат проверен именно через этот узел. Подтверждение не продлевает срок результата. Проверки страны вручную подтвердить нельзя.

Проверки выполняются временным процессом через проверяемый прокси. Рабочее подключение не переключается, изменения не применяются. Ручные proxy-ссылки этим фильтром не проверяются. Список «Google AI» в маршрутах секции помогает направить связанные домены, но сам по себе не проверяет узел; маршруты автоматически не меняются.

### Применение

Проверка и обновление конфигов готовят данные для последующего применения. Нажатие «Применить» является отдельным действием.

Если секция поддерживает изолированное применение, её кнопка меняет только эту секцию. Остальные черновики сохраняются в открытой странице. При отсутствии такой возможности нужен общий перезапуск. Интерфейс показывает доступный вариант; одинаковый внешний вид не означает наличие всех возможностей Engine в legacy.

## Бенчмарк DNS в PE

«Подобрать рабочую пару» сначала измеряет выбранные основные и bootstrap DNS отдельно. Затем DNS и HTTPS через активные секции Podkop проверяются у финалистов: сначала до восьми пар, включая текущую. При нехватке рабочих вариантов набор расширяется. Лидеры проходят повторную проверку.

Лучшая пара определяется среди проверенных финалистов. Кандидат, у которого HTTPS не проверялся, не считается отказавшим. «Полный перебор всех пар» проверяет все выбранные сочетания и занимает больше времени.

Варианты «только для сравнения» могут участвовать в полном переборе, но не становятся рекомендацией. Варианты «только вручную» не входят в автоматический подбор. Успешный отдельный DNS-запрос ещё не подтверждает HTTPS через Podkop.

При выборе лидера сначала учитываются сбои, затем скорость. Оценка времени складывается из среднего DNS и HTTPS: меньшее значение лучше.

«Подобрать и полностью проверить» после быстрого подбора проверяет лидеров по полной выборке по очереди. Если первая пара не проходит, проверяется следующая. Рекомендация появляется после успешной полной проверки. «Проверить пару» запускает полную проверку выбранной вручную пары; при таймауте предусмотрен один повтор.

Таблица результатов свёрнута по умолчанию и имеет собственную прокрутку. Рекомендуемая пара расположена первой, затем рабочие варианты по рейтингу, внизу нерабочие. Подробности по секциям и адресам раскрываются в результатах.

Измерения используют изолированную копию маршрутов с текущими выбранными прокси. Результат относится к проверенным адресам и текущему подключению, а не ко всем функциям приложений. Закрытие окна отменяет проверку. DNS не применяются автоматически.

### Bootstrap и резерв

Bootstrap находит IP основного DNS, если его фактический адрес задан именем. DoH/DoT могут использовать имя, даже когда в каталоге показан IP. Точный адрес и необходимость bootstrap указаны в результате пары. Если фактический адрес является IP, bootstrap для этого адреса не нужен.

Отдельная кнопка «Проверить bootstrap» проверяет выбранный сервер. Успех такой проверки не заменяет DNS и HTTPS проверку всей пары.

Bootstrap не обходит блокировки сайтов. Недоступными могут оказаться DNS-сервер, его порт или защищённое соединение. Таймаут сам по себе не доказывает блокировку РКН; пару нужно проверять на своём подключении.

Подбор резервной пары исключает провайдера текущего основного DNS. Резерв проходит полную проверку пары и отдельную проверку bootstrap. «Сохранить как резерв» заполняет ожидающие изменения формы, не меняя текущие DNS. Сохранение настроек и включение автоматического резерва выполняются отдельно.

Автоматический резерв после двух последовательных отказов активной пары проверяет другую пару, переключает DNS-тракт и проверяет sing-box/FakeIP. При неудачном переключении выполняется откат. Автоматического возврата на предпочтительную пару нет, чтобы не создавать постоянные переключения. Выбор другого провайдера снижает общую зависимость, но не гарантирует доступность резерва.

## Legacy без Engine

Интерфейс подписок и смысл фильтров совпадают с PE. Проверки используют установленный sing-box; переход на Engine для них не требуется. Доступность отдельных протоколов и изолированного применения определяется возможностями конкретного роутера.

DNS-бенчмарк legacy имеет собственные режимы «Авто», «Экономичный» и «Полный». Экономичный режим сокращает дополнительные проверки и выполняет работу последовательно. Пропущенная дополнительная проверка не считается успешной. Кнопки двухэтапного PE-подбора и legacy-бенчмарка относятся к разным контурам; описание PE не является обещанием их наличия на старой версии.

При недостатке ресурсов проверка может ожидать освобождения памяти или завершиться с указанием причины. Рабочие DNS остаются прежними. Применение и откат доступны только отдельными действиями.
