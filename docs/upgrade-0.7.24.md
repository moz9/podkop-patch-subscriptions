# Подготовка Podkop 0.7.24

Этот набор исходников подготовлен для Podkop 0.7.24 и Podkop Engine
1.14.2-pdk-r14. Он публикуется только как тестовый кандидат и не установлен на роутерах.
Legacy-ветка для Pioneer остаётся без Engine.

## Изменения

FakeIP-правила служебных доменов отделены от правил списков. При сохранении
конфига удаляется DNS route без условий, который иначе перехватывал бы все
запросы. Это изменение из
[Podkop 0.7.24](https://github.com/itdoginfo/podkop/compare/0.7.23...0.7.24).

Переключатель uTLS fallback доступен только при поддержке движком и выключен
по умолчанию. Выбранное значение сохраняется в конфиге отдельного процесса
секции и в изолированных проверках. Проверки не используют рабочий Clash API
или рабочий DNS-кэш.

В набор входят наши подписки, проверки страны Google/IP, изолированное
сохранение DNS-резерва и защита бенчмарка по памяти, времени и владельцу
процесса. Подтверждение DNS-пары связано с содержимым бинарника Engine и его
полным выводом версии. После замены движка пару нужно проверить заново.

## Граница установки

Манифест имеет `releaseStatus: prepared`. Центр обновлений показывает этот
набор как заблокированный. Установщик принимает только уже установленные
Podkop/LuCI 0.7.24 и точный Engine 1.14.2-pdk-r14 с нужными расширениями.
Он не обновляет пакеты Podkop/Engine; запуск сервисов по умолчанию отложен.
В старом пути установщика остаётся условная установка зависимостей и модулей
uhttpd. Поэтому этот набор не предназначен для запуска на рабочем роутере.
Историческая команда `m` также заблокирована в этом наборе.

Перед установкой нужен отдельный проверенный переход пакетов. Для него
необходимо сохранить конфиги и замороженный граф работающих секций вместе
с локальными списками. Нужно проверить конфиг новым движком, сохранить
прежние пакеты и учесть файлы, которые меняет пакет Engine: init-скрипты,
failsafe, списочные hooks и UCI defaults. Проверка свободного места должна
покрывать обновление и откат, включая прежний бинарник, который ещё держат
запущенные процессы.

Настройки одного роутера не переносятся на другой. Этот переход не применяет
рекомендованную DNS-пару и не включает uTLS fallback автоматически.

## Проверка исходников

В Linux с Node.js и jq:

```sh
sh tests/run-0724-preparation.sh
node scripts/update-release-hashes.mjs --check
```

`sing-box check` подтверждает совместимость JSON с движком. Он не подтверждает
доступность DNS, работу сервисов через прокси или стабильность на самом роутере.
После отдельной установки понадобятся проверки живых процессов и внешнего
клиентского соединения с возможностью отката.
