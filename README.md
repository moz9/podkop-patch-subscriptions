# Podkop PE

Экспериментальная версия нашей обвязки для Podkop `0.7.23` с
[podkop-engine](https://github.com/FiyeroT/podkop-engine) `1.13.21-pdk-r11`.
Ветка `podkop-pe` имеет отдельный канал обновлений. Обычная версия остаётся
в `main`; её установщик не переключает роутеры на PE.

Оригинальный проект: [itdoginfo/podkop](https://github.com/itdoginfo/podkop).

PE сохраняет режим «Микс», управление подписками, фильтры тегов и центр
обновлений. DNS-бенчмарк использует схему выбора и проверки пары из ZeroBlock.
Полный установщик добавляет ByeDPI, WARP и ZeroTier.
Новый runtime собран поверх официального `0.7.23`; движок устанавливается
как пакет `podkop-engine`, а исполняемый файл называется `sing-box`.

Настройки резервных URLTest-узлов и проверки загрузки 64 КиБ доступны также
для подписок. XHTTP разбирает движок через `tools decode-link`; транспорт
показывается как поддерживаемый только при наличии нужных возможностей.
Проверка загрузки и резервные узлы не гарантируют доступность каждого сервиса.

## Управление подписками

Во вкладке «Подписки» у каждого источника есть отдельная галочка включения.
Рядом расположены кнопки обновления, пинга и бенчмарка только этой подписки;
общие кнопки вверху выполняют действие для всех подписок. Выбор источника
сохраняет кеш и результаты тестов остальных подписок. Наведите указатель на
галочку или значок, чтобы увидеть подсказку.
После «Применить» отключённая подписка не попадает в рабочие группы Podkop.
Её конфиги остаются видимыми, сохраняют индивидуальные галочки и доступны для
обновления, пинга и бенча. Диагностические запросы выполняются отдельным
временным процессом sing-box на loopback, без переключения рабочего прокси.

Состояние подписки привязано к её URL, поэтому перестановка списка его не меняет.
Одинаковый конфиг из нескольких подписок остаётся рабочим, если включён хотя бы
один его источник. В каждой секции должен оставаться хотя бы один включённый
поддерживаемый конфиг. При недоступности сервера подписки сохраняется предыдущий
кеш этой подписки; доступные подписки обновляются независимо, а интерфейс
показывает ошибку у соответствующего источника.

Компактный индикатор показывает состояние операций: «Готово», «Podkop занят»,
«Обновляется», «Нужно применить» или «Ошибка». Занятость проверяется на роутере;
при недоступном статусе конфликтующие действия заблокированы. Это не проверка
доступности интернета или всех прокси. Повторное нажатие не запускает дубликат.
При ошибке применения и переходе между вкладками несохранённые галочки остаются
в открытой странице (перезагрузка страницы их сбросит). Выбор переносится при
однозначном совпадении конфигов; для действительно новых узлов галочки нужно проверить.

Версия PE: `20261007-pe-v5`. Обновление PE доступно через команду ниже и
во вкладке «Диагностика» → «Обновления».

По умолчанию все поддерживаемые конфиги включённых подписок участвуют автоматически, но в работу попадают только прошедшие фильтры тегов. Дополнительный тумблер «Ручной отбор конфигов» включает режимы «Только выбранные» и «Все, кроме выключенных». При отключении ручного отбора сохранённые галочки и исключения не стираются, но временно не ограничивают рабочий набор. Существующий явно настроенный режим сохраняется при обновлении: чтобы перейти на отбор только по тегам, выключите тумблер и примените. Выбор независим для каждой секции. Пустой рабочий набор отклоняется; все изменения применяются одной транзакцией с восстановлением при ошибке.

### Фильтры тегов и свёрнутые подписки

В каждой секции есть компактные списки «Разрешённые теги» и «Исключённые теги».
Короткие префиксы (`EU`, `RU`, `US`, `SE`, `FI` и другие) определяются из реальных названий узлов; флаг и буквенный код одной страны считаются одним тегом. Полное название страны не требуется;
нужные теги выбираются галочками, без ручного ввода названий. Сохранённые
пользовательские шаблоны также остаются в списке. Пустой список разрешения
не ограничивает узлы. Исключение имеет приоритет над разрешением.

Правила сохраняются для секции и проверяются снова после изменения подписки.
Так новые нежелательные узлы не попадут в рабочий набор после применения
обновлённого кеша. В режиме «Только выбранные» новый узел остаётся выключенным,
даже если подходит под фильтр. Фильтр не меняет сохранённые галочки отдельных
конфигов и не включает выключенную подписку.

Все конфиги остаются видимыми после раскрытия подписки; их можно пинговать
и проверять бенчмарком. Перед применением интерфейс показывает размер будущего
рабочего набора. Если в секции не останется ни одного включённого
поддерживаемого узла, применение отклоняется с сохранением прежних настроек.
Фильтры, режим выбора и галочки применяются одной транзакцией.

После применения интерфейс читает сохранённый выбор напрямую с роутера, не сбрасывая другие несохранённые правки LuCI.
При таймауте ответа показывает «Проверяем результат» и без повторной записи сверяет режим, теги, конфиги и подписки после завершения операции. «Применено» появляется только при полном совпадении; неподтверждённый выбор сохраняется для проверки пользователем.
Временный сбой чтения повторяется
до трёх раз. При сохранении ошибки список и черновик остаются на экране;
кнопка «Повторить чтение подписок» восстанавливает отображение без скачивания
подписок, повторного применения или перезапуска Podkop.

На дашборде доступны «Скрыть недоступные», «Скрыть медленные» и порог задержки
в миллисекундах. Это только фильтры отображения: рабочий набор не меняется.
Активный выбор и непроверенные узлы остаются видимыми. Предпочтения сохраняются
в этом браузере; по умолчанию оба фильтра выключены, порог — 1000 мс.

Секции и подписки по умолчанию свёрнуты. Заголовки показывают количество
конфигов и узлов, допущенных к работе, а также ошибки подписок. Раскрытое
пользователем состояние сохраняется при обновлении данных в открытой странице;
после перезагрузки страницы всё снова свёрнуто.

### Обновление подписок без прерывания работающего прокси

Плановое обновление и кнопки обновления подписок теперь только получают кеш.
Активный конфиг, sing-box, DNS и сетевые правила при этом не меняются.
Новые серверы ожидают явного применения; повторное плановое обновление не
применяет их автоматически. Ошибка скачивания сохраняет прежний кеш.
Это осознанное изменение поведения: новый или изменённый сервер не начинает
использоваться сразу после скачивания подписки.

Для явного применения в согласованное окно обслуживания (возможен разрыв
текущих прокси-соединений):

```sh
PODKOP_SUBSCRIPTION_APPLY_NOW=1 /usr/bin/podkop subscription_update
```

Команда получает подписки и применяет накопленные изменения всех секций.
При неизменном итоговом конфиге сигнал перезагрузки не отправляется. Само
применение через SIGHUP не гарантирует сохранения TCP/UDP-сессий. Предыдущий
конфиг сохраняется на время применения для восстановления при обнаруженной
ошибке; проверка наличия процесса не является доказательством работы трафика.
Обычный перезапуск Podkop или роутера также использует обновлённый кеш.
Маркер ожидания находится в `/tmp/podkop-subscription-reload.pending` и не
является постоянным журналом. Кнопка «Применить» во вкладке «Подписки» активна
также при наличии скачанных, но ещё не применённых конфигов.
Установка самого патча может перезапустить сервисы: обновляйте сначала один
роутер в согласованное окно, а не всю сеть одновременно.

## Установка и обновление на OpenWrt

Выполнять уже внутри SSH-сессии на роутере:

```sh
wget -O /tmp/podkop-pe "https://raw.githubusercontent.com/moz9/podkop-patch-subscriptions/podkop-pe/i?t=$(date +%s)" && sh /tmp/podkop-pe
```

Это команда для первой установки и обновления PE. Текущая сборка рассчитана
на `aarch64_cortex-a53` с `apk` или `opkg`. На другой архитектуре установщик
останавливается до изменения пакетов. Нужны рабочий HTTPS, верное время и
доверенные сертификаты. Сохраните резервную копию перед переходом на PE.

Что делает установщик:

- если Podkop не установлен, ставит закреплённый Podkop `0.7.23`, podkop-engine и LuCI, затем применяет обвязку PE;
- несовместимые версии и конфликтующие сервисы требуют проверки перед миграцией;
- на уже установленном Podkop `0.7.23` проверяет пакеты и возможности движка; недостающие PE-пакеты устанавливает только с разрешёнными обновлениями пакетов;
- использует закреплённые Podkop `0.7.23` и движок `1.13.21-pdk-r11` с проверкой SHA-256, а не произвольный последний официальный релиз;
- установленный Podkop `0.7.22` и старее требует отдельной миграции; даже `PODKOP_PATCH_FORCE_PODKOP_UPDATE=1` не обходит этот запрет;
- на `opkg` установленный штатный `sing-box` / `sing-box-tiny` требует отдельной замены; рабочий движок установщик автоматически не удаляет;
- если обвязка PE уже актуальна, завершает работу с `PODKOP_PATCH_NOOP=1`;
- сохраняет настройки Podkop, подписки, кеш подписок и исключённые конфиги.

### Переход со старого Podkop

Команда выше **не является автоматической миграцией с 0.7.22**. Перед переходом
сохраните резервную копию OpenWrt и отдельно `/etc/config/podkop`, `/etc/podkop`,
пакеты/настройки WARP, ByeDPI и ZeroTier. Проверьте свободное место именно в
`/overlay`: размер скачанного APK не равен размеру установленного движка.
ZeroTier не удаляйте и не переустанавливайте без отдельной необходимости.

Миграция меняет пакеты Podkop/LuCI и движок, поэтому выполняйте её через LAN
в отдельное окно обслуживания. Сначала нужен официальный Podkop `0.7.23`
и совместимый PE-движок, затем команда этой ветки накладывает нашу обвязку.
Самостоятельно запускать официальный обновитель поверх активного режима
`subscription_urltest` нельзя: штатный Podkop не знает этот тип конфигурации.
Нужно заранее сохранить рабочую конфигурацию и спланировать её восстановление.
Резервная копия патча позволяет вернуть файлы/настройки, но не откатывает
автоматически установленный набор пакетов. На роутере с почти заполненной
флеш-памятью сначала требуется проверка места и отдельный план миграции.

### Подготовка места без удаления сервисов

Если к роутеру подключён отдельный ext4-диск `/mnt/storage`, старые резервные
копии и тестовые снимки Podkop можно перенести туда, освободив флеш. Сначала
запустите проверку, которая ничего не меняет:

```sh
wget -O /tmp/prepare-pe-storage "https://raw.githubusercontent.com/moz9/podkop-patch-subscriptions/podkop-pe/scripts/prepare-pe-storage.sh?t=$(date +%s)" && sh /tmp/prepare-pe-storage --check
```

Для переноса: `sh /tmp/prepare-pe-storage --apply`. Скрипт сначала сохраняет
полный снимок `/overlay/upper` в закрытом каталоге
`/mnt/storage/.podkop-pe-private`, затем переносит только перечисленные в
скрипте исторические копии из `/root`. Оригинал удаляется только после
сверки содержимого, прав, владельцев и ссылок. Используемые процессами или
указанные в автозапуске пути не трогаются. При отсутствии отдельного диска
скрипт останавливается, чтобы не записать копию обратно во флеш.

ByeDPI, WARP, ZeroTier, установленные пакеты и настройки не меняются, сервисы
не перезапускаются. Скрипт **не устанавливает PE** и не обходит запрет перехода
с Podkop `0.7.22`. Освобождённое место измеряется после переноса: логический
размер файлов не равен реально занятому месту на сжатой UBIFS. При будущей
установке патча резервные копии можно направить на внешний диск переменной
`PODKOP_PATCH_BACKUP_ROOT=/mnt/storage/.podkop-pe-private`.

Если `raw.githubusercontent.com` недоступен, запасной вариант через CDN. После свежей публикации CDN может некоторое время отдавать предыдущую версию установщика:

```sh
wget -O /tmp/podkop-pe https://fastly.jsdelivr.net/gh/moz9/podkop-patch-subscriptions@podkop-pe/i && sh /tmp/podkop-pe
```

Если на роутере сломан DNS, но прямой HTTPS до GitHub доступен:

```sh
curl --resolve raw.githubusercontent.com:443:185.199.108.133 -fSL https://raw.githubusercontent.com/moz9/podkop-patch-subscriptions/podkop-pe/i -o /tmp/podkop-pe && sh /tmp/podkop-pe
```

Этот вариант помогает скачать наш установщик без DNS. Для первой установки официального Podkop всё равно нужен рабочий доступ к GitHub/OpenWrt downloads.

Установщик:

- перед обновлением сохраняет `/etc/config/podkop` и `/etc/podkop`, чтобы не потерять настройки Podkop, кеш подписок и исключённые конфиги;
- проверяет фиксированную основу Podkop 0.7.23 и совместимый Podkop Engine; переход с 0.7.22 требует отдельной подготовки;
- скачивает полный runtime PE, LuCI-файлы и русскую локализацию;
- делает резервную копию изменяемых файлов в `/root/podkop-patch-subscriptions-backup-*`;
- по умолчанию хранит только 2 последние резервные копии;
- устанавливает наши обвязки поверх Podkop 0.7.23 с Podkop Engine;
- проверяет shell-синтаксис;
- при первом временном сбое запуска один раз повторяет запуск Podkop перед откатом;
- перезагружает Podkop и LuCI;
- при ошибке этапа патча возвращает резервированные файлы. Уже изменённые пакеты и настройки веб-сервера предыдущих этапов автоматически не откатываются.

## Установка полного набора одной командой

Для установки Podkop с нашим патчем, ByeDPI, Cloudflare WARP и ZeroTier
выполните через SSH от root:

```sh
wget -O /tmp/owrt-pe https://raw.githubusercontent.com/moz9/podkop-patch-subscriptions/podkop-pe/a && sh /tmp/owrt-pe
```

Скрипт `a` рассчитан на OpenWrt с `opkg` или `apk` и архитектурой
`aarch64_cortex-a53`: это ограничение текущего установщика WARP.
На другой архитектуре он остановится до установки пакетов. Нужны рабочий
интернет, верное время и доверенные сертификаты HTTPS. Сначала примените
или отмените несохранённые изменения LuCI.

Если Podkop отсутствует, скрипт устанавливает официальный Podkop и затем
наш патч. После этого устанавливает ByeDPI, WARP и ZeroTier.
Недостающие `jq`, `curl` и сертификаты устанавливаются через пакетный
менеджер. Общего обновления всех пакетов и перезагрузки роутера нет.
Перед запуском установщиков скрипт скачивает их, проверяет SHA-256
и shell-синтаксис. Повторный запуск сохраняет существующие настройки.

При первой установке WARP регистрируется и подключается, но весь трафик
роутера в туннель автоматически не переводится. ByeDPI запускается
с настройками своего установщика. Подписки и списки маршрутизации Podkop
нужно задать самостоятельно; для ZeroTier нужны Network ID и разрешение
роутера в вашей сети. Частные идентификаторы в скрипт не встроены.

Установщики могут перезапустить Podkop, LuCI и ZeroTier. Запускайте команду
в подходящее окно обслуживания, особенно при подключении через ZeroTier.
При ошибке скрипт останавливается, сообщает проблемный этап и перечисляет
завершённые. Уже установленные компоненты остаются; единого отката всего
набора нет. После устранения причины можно повторить ту же команду.

## Что добавляет патч

- режим `Микс` для чтения proxy-конфигов из HTTP/HTTPS-подписок и ручного добавления отдельных proxy-ссылок;
- поддержку нескольких подписок в одной секции;
- кеш последней рабочей версии подписки;
- бесшовную активацию обновлённого кеша подписок через быструю перезагрузку только sing-box: nftables и dnsmasq не удаляются, а при неизменившемся активном конфиге перезагрузка вообще не выполняется;
- поддержку подписок Remnawave с ограничением по устройствам: приватный идентификатор роутера отправляется только после явного запроса HWID от провайдера, а подставные конфиги «приложение не поддерживается» безопасно исключаются;
- фильтрацию неподдерживаемых Podkop конфигов до генерации sing-box;
- отдельный список неподдерживаемых конфигов в дашборде;
- вкладку `Подписки` для включения и исключения отдельных конфигов;
- транзакционное применение изменений сразу во всех секциях с одной фиксацией и одним перезапуском Podkop; при ошибке после записи настройки и кеши возвращаются из снимка;
- синхронизацию вкладки с фактическим состоянием после ошибки, чтобы интерфейс не сообщал об отказе при уже применённых изменениях;
- адаптивные карточки подписок, DNS-результатов, диагностики и дашборда для стандартной темы LuCI и Proton2025, включая мобильные экраны;
- компактные действия во вкладке `Подписки`: обновить подписки, ping, быстрый тест скорости, применить и сбросить выбор; обновление самого патча находится в `Диагностике`;
- кеш community subnet списков, чтобы быстрый reload не оставлял `podkop_subnets` пустым;
- отдельный DNS-бенчмарк с таблицами основного и bootstrap DNS, числом успешных запросов и средним временем ответа;
- измерение UDP, DoH и DoT в отдельном процессе Podkop Engine без остановки рабочего Podkop;
- возможность оставить для теста один или два протокола, чтобы сократить время проверки;
- повторные DNS-запросы, проверка ответа для несуществующего домена и DNS-имён Google Play, ChatGPT и других прикладных сервисов;
- после установки выбранной пары выполняются небольшие Google Play download и ChatGPT/OpenAI HTTPS canary, включая официальный OIDC discovery входа ChatGPT; если обязательный загрузочный тракт недоступен, прежние DNS автоматически восстанавливаются;
- отдельные проверки выбранных community-списков Podkop, включая YouTube, Telegram, Meta, Discord, Twitter и Google AI; недоступный выбранный сервис исключает DNS из надёжных рекомендаций;
- community-проверки используют отвечающие DNS-имена из актуальных списков allow-domains, чтобы не отклонять все DNS из-за неактивного домена или корня CDN без A-записи;
- выбор основных и bootstrap DNS для проверки, чтобы не запускать полный каталог при каждом тесте;
- компактный безопасный набор по умолчанию: Cloudflare, Google и Control D; AdGuard Unfiltered и Mullvad остаются доступны для явного ручного включения;
- сохраняемые пользовательские DNS-кандидаты отдельно для UDP, DoH и DoT;
- ручной выбор пары из рабочих результатов; применение разрешено только после успешной DNS-проверки именно этой пары и HTTPS-проверок Google Play и ChatGPT через текущие маршруты Podkop;
- после применения проверка повторяется через новый рабочий DNS-тракт; недоступность ChatGPT напрямую через провайдера сама по себе не означает неисправность DNS;
- повторная проверка обязательна, если настройки изменились или подтверждение старше пяти минут;
- Yandex доступен только как bootstrap DNS и исключён из основного и резервного upstream;
- отдельная кнопка отмены проверки и сохранение последнего отчёта; измерения сами не меняют настройки DNS;
- лёгкий watchdog без дополнительного DNS-сервиса: после двух последовательных отказов активной пары он проверяет вторую, переключает весь DNS-тракт Podkop, проверяет sing-box и FakeIP и автоматически откатывает неудачное переключение;
- отдельные ручные поля протокола, основного и bootstrap DNS для резервной пары; при ручном изменении предпочтительной пары штатная кнопка LuCI снова активирует её;
- применение проверенной пары с повторной проверкой прикладных доменов через sing-box и dnsmasq, проверкой FakeIP, автоматическим откатом при ошибке и отдельной кнопкой ручного отката;
- локальная проверка FakeIP через DNS самого роутера без зависимости от внешнего тестового сайта; недоступные браузерные проверки при удалённом доступе или Secure DNS показываются как предупреждение, а не как поломка Podkop;
- перезагрузка страницы после успешного применения или отката DNS, чтобы старая форма LuCI не перезаписала новые настройки;
- компактный центр обновлений в диагностике: проверка Podkop и патча, безопасное совместное обновление, блокировка неподдерживаемых релизов, просмотр и копирование терминального лога;
- русские строки интерфейса для добавленных элементов.

Схема бенчмарка изучена по установленному ZeroBlock 0.8.5-r44. Его публичный
[репозиторий](https://github.com/routerich/ZeroBlock) пока не содержит исходников
демона; PE использует собственный worker. Bootstrap здесь остаётся UDP, как в
Podkop 0.7.23. Зашифрованный bootstrap из ZeroBlock в эту версию не перенесён.

Совместимость публикуется в `openwrt/update-manifest.json`. Новая официальная версия Podkop становится доступна через кнопку обновления только после добавления её в `supportedPodkopVersions` и проверки патча на этой версии.

PE поддерживает Podkop `0.7.23`. Старые runtime-файлы и серия `patches/`
сохранены для истории и регрессионных тестов; установщик PE их не применяет.

## Патч для исходников

Runtime-установка PE использует `openwrt/runtime-0.7.23/` и файлы обвязки
из `openwrt/`. Историческая серия `patches/` не является способом сборки PE.
